# Kernel-Web Project Memory (Persistent Context)

- **Location**: /Users/louis/Projects/LaswitchTech/kernel-web

- **Repo**: https://github.com/LaswitchTech/kernel-web/tree/dev

- **Only /public is web-accessible**

## Architecture (4 Layers)
```
[Kernel Core] → [Plugins] → [Layouts] → [Themes]
```
- **Core**: routing, DI container, auth, plugin/theme/layout loaders, DB layer, config system
- **Plugins**: /lib/plugins/{Name}/ with plugin.json manifest (name,version required), src/, routes.php, migrations/, views/
- **Layouts**: /lib/layouts/ — panel.php (admin), app.php (app), blank.php (auth)
- **Themes**: /lib/themes/ — Bootstrap 5 + LESS variables, dark/light mode
- **Core must be application-agnostic** (no NetMon-specific logic)
- **Plugin-over-core**: when unsure, prefer plugin until core need is clear
- **Separation**: Controllers → orchestration, Services → business logic, Repositories → data access, Kernel → infrastructure, Plugins → features

## Coding Discipline
- Small safe changes, never modify unrelated files
- Readable over clever, explicit over magic
- Respect existing architecture before introducing new patterns
- Thin controllers, focused services/repositories
- No hardcoded configurable paths, no hidden side effects
- No premature abstraction — extract helpers only at 3+ repeats
- Architectural consistency over backward compatibility (early dev)
- Document breaking changes (routes, config keys, plugin hooks, view contracts, DB schema)
- **Modern PHP 8.x ONLY** (readonly VOs, union types, match, constructor prop promotion, native str_contains/str_starts_with)
- **Never revert to PHP 7.x compatibility**
- Avoid heavy dependencies — document all additions with rationale
- Plan before coding: explain what, why, which files, risks, priority alignment

## Config Architecture
- **File-backed is primary**: config/local.php (array_replace_recursive over config/app.php)
- **Precedence**: .env → config/app.php → config/local.php → hardcoded defaults
- **ConfigOverrideService**: all UI-driven config writes to config/local.php via dot-notation keys (e.g. auth.two_factor.enforced), atomic file writes
- **system_settings DB table is DEPRECATED for config** — use only for true per-user runtime state
- **Instance-wide non-secret settings → config/local.php**
- **Sensitive secrets → encrypted DB or config/local_secrets.php**
- **APP_DEBUG** controls debug/dev-tools via config/app.php debug key

## Global View Context
- Every layout must begin with **ViewGlobals::contextFromScope()** as single entry point
- **Never** silently return from partials on missing globals — that's a context pipeline bug, fix at layout entry point
- No isset() fallbacks for structural variables in partials
- Guaranteed globals: $Config, $Auth, $User, $Permissions, $Helper, $Layout, $Router, $Kernel + derived
- Guest-safe defaults always ($User is valid array or null, $Permissions is always array)
- Container is source of truth

## Plugin System
- **Manifest**: plugin.json in /lib/plugins/{Name}/ (name, version required; description, enabled, requires, dependencies, permissions, routes, migrations, services, hooks, menus optional)
- **Lifecycle states**: discovered → enabled/disabled/invalid
- **Boot flow**: discover → validate → check deps → register permissions → register services → register hooks/menus → store in container → include routes.php
- **Hook format**: Class@method callback (optional install/enable/disable hooks)
- **Services**: {class, singleton:true/false, args[]} with container-aware args
- **Dependencies**: type:slug format (e.g., plugin:notes), semver constraints via version_compare()
- **Constraints**: exact, >=, >, <=, <, ^, ~; invalid = fail closed
- **Resolver**: ExtensionDependencyResolver with checkInstall/checkEnable/checkUninstall/checkDisable/detectCircular
- **Enforcement**: install/enable/disable/uninstall block on dependency failures; no auto-install
- **Hooks run after plugin loaded** into registry (not during discovery)
- Plugins must never crash kernel if they fail — self-contained
- Directory: src/, routes.php, migrations/, views/, hooks.php, menus.php, plugin.json

## Routing
- Central router with plugin route injection
- Priority override: plugin=1 (default), kernel=0 (default). Higher wins on same path
- Clean URLs, RESTful structure, /api/ prefix for JSON
- Routes in routes/web.php with middleware
- Layout override: app/Views/layouts/ → /lib/layouts/ → safe default
- Landing page: GET / via HomeController@index (priority 0), overridable by plugins at priority 1
- Admin routes: /admin/* with WebAuth + WebPermission middleware
